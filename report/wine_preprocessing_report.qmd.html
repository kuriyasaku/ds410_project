1 Introduction

This report explains, step by step, how I cleaned and featurized the Kaggle WineEnthusiast dataset using PySpark in the notebook wine_preprocessing_pyspark_c.

For each stage I describe:

  • Motivation – why this step is needed.
  • What we did – the main operations and code ideas.
  • Result – how the dataset changed, and what artifacts were produced.

The final goal of this pipeline is to generate:

  • a clean, standardized base dataset for exploration; and
  • an ML-ready dataset with a single features vector that combines numeric, categorical, and text information, so that we can directly plug it into regression, classification, or clustering models.

2 Dataset

2.1 Raw data

  • Source: Kaggle WineEnthusiast ratings dataset.
  • Original size: about 130k rows.
  • Key columns:
    country, description, designation, points, price, province, region_1, region_2, taster_name, taster_twitter_handle, title, variety, winery.

2.2 Motivation

We treat the Kaggle export as the only raw input.
All downstream artifacts (clean data, features, ML models) must be reproducible from this single CSV file plus the PySpark notebook.

3.5 Step 3 — Read Data and Perform Initial Inspection (Infer / Correct Data Types)

3.5.1 What We Did

In this step, the goal was to load the raw CSV safely, inspect its structure, remove unnecessary columns, and correct data types for downstream analysis. The process included four main actions:

3.5.2 1. Loading the CSV with Spark

We used spark.read.csv() with several important options:

  • header=True: tells Spark to treat the first row as column names.
  • multiLine=True: allows records that contain line breaks inside quoted text (common in user-generated descriptions).
  • escape='"': allows proper parsing of embedded quotes.
  • inferSchema=True: automatically infers column data types from the raw file.

This gives us an initial DataFrame df_raw along with basic metadata (row count and column names).

3.5.3 2. Removing Useless or Auto-Generated Columns

Some CSV exports — especially those from Kaggle or Excel — contain extra columns such as:

  • "Unnamed: 0"
  • "_c0"
  • "index"

These are not real variables and are usually accidental index columns.
Therefore, we looped through a list of known junk names and removed them if they exist.

3.5.4 3. Fixing Incorrect Data Types

Two variables require special attention:

3.5.4.1 a. points

Originally read as string in some CSV versions.
We explicitly convert it to integer using:

  • .cast(IntegerType())

3.5.4.2 b. price

Some price values contain commas (e.g., "1,200").
Spark cannot convert such strings directly into numbers, so we:

  1. Cast price to string to ensure regex operations can apply
  2. Use regexp_replace to remove commas
  3. Cast the cleaned string into a proper DoubleType

This ensures numerical columns can be analyzed, plotted, and modeled without errors.

3.5.5 4. Previewing the Cleaned Data

Finally, we print to make sure:

  • The schema (printSchema()), to confirm correct data types
  • The first five rows (show(5)), to perform a quick sanity check

This step verifies that our transformations were successful and that the DataFrame df is now ready for further cleaning or exploratory analysis.

3.6 Step 4 — Quick Data Quality Check

3.6.1 Purpose

Before deciding how to clean or model the data, we need a quick overview of which columns contain missing values and how severe the missingness is. This helps us determine: - which variables may need imputation, - which columns might be too sparse to keep, - and where data issues could affect modeling later.

3.6.2 What We Did

We wrote a small helper function null_report() that: - counts null or empty-string values for each column, - calculates the missingness percentage, - and returns a sorted summary (most missing → least missing).

Running the function shows: - region_2, designation, and some taster-related fields have high missingness, - core fields like description, variety, and country are largely complete,

region_2 column contains 79,460 missing values, accounting for 61.14% of the entire dataset

from pyspark.sql import functions as F

def null_report(_df):
    total = _df.count()
    stats = [
        F.count(F.when(F.col(c).isNull() | (F.trim(F.col(c)) == ""), c)).alias(c)
        for c in _df.columns
    ]
    row = _df.select(*stats).collect()[0].asDict()
    return sorted([(k, v, round(v/total, 4)) for k, v in row.items()],
                  key=lambda x: x[1], reverse=True)

3.7 Step 5 — String Normalization and Cleaning Functions

3.7.1 Purpose

Text columns in the raw dataset come from many different sources and often contain inconsistent formatting.
Before modeling or visualization, we need a standardized version of each text field (norm) so that:

  • “US”, “Us”, and “us” are treated as the same category
  • accented characters (e.g., “São Paulo”) are normalized
  • extra spaces or irregular formatting do not create false categories
  • downstream grouping, clustering, and ML models become more reliable

3.7.2 What We Did

We created a Python-based normalization function that:

  1. Converts accented characters to ASCII using Unidecode
  2. Strips leading/trailing spaces
  3. Forces all text to lowercase
  4. Collapses multiple whitespaces into one

We applied this function to key categorical/text fields such as
country, province, region_1, region_2, variety, winery, taster_name, etc.
For safety, we kept the original columns and created new ones with the suffix *_norm to compare differences.

The preview confirms normalization is working as expected.

import re, unicodedata
from unidecode import unidecode

def normalize_text_py(s: str) -> str:
    if s is None:
        return None
    # ASCII
    s = unidecode(str(s))
    s = s.strip().lower()
    s = re.sub(r"\s+", " ", s)
    # can add more
    return s

normalize_udf = F.udf(normalize_text_py, T.StringType()) #Register the Python function as a Spark UDF so that the Spark DataFrame can call our custom text-cleaning function

# standardize string（keep original，add *_norm for checking）

3.8 Step 6 — Deduplication Strategy

3.8.1 Purpose

Large text-based datasets often contain repeated reviews or near-identical entries.
To avoid bias in later analyses or ML models, we need a reliable way to detect and remove duplicates—even when the text is slightly different (punctuation, casing, spacing, etc.).

3.8.2 What We Did

We created a fingerprinting method that identifies duplicates based on meaningful text content rather than row position:

  1. Normalize the review text

    • Convert description to lowercase
    • Remove punctuation and collapse into a simple alphanumeric string
      This captures the core meaning while ignoring formatting noise.

  2. Build a combined fingerprint
    We merge three stable fields:

    • title
    • winery
    • normalized description

    Then compute a SHA-256 hash (row_fingerprint) from this combination.
    Each unique review should produce a unique hash.

  3. Drop duplicates based on the fingerprint
    We remove repeated SHA-256 fingerprints and drop the helper columns afterwards.

3.8.3 Result

This process removed 9,985 duplicate rows from the dataset.
The repeated Spark header warning is the same harmless CSV-header issue noted earlier.

# Step 6 — Deduplication Strategy

# 1. Normalize description
df = df.withColumn(
    "desc_fingerprint",
    F.lower(F.regexp_replace(F.col("description"), r"[^A-Za-z0-9]+", " ")) # Remove all non-alphanumeric characters and replace them with a space
)

# 2. Combine fields and compute SHA-256 fingerprint
df = df.withColumn(
    "row_fingerprint",
    F.sha2(F.concat_ws( #Combine title, winery, and desc_fingerprint and compute a SHA-256 hash
        "||",
        F.coalesce(F.col("title"), F.lit("")),
        F.coalesce(F.col("winery"), F.lit("")),
        F.coalesce(F.col("desc_fingerprint"), F.lit(""))
    ), 256)
)

# 3. Deduplicate
before = df.count()
df_dedup = (    #Perform deduplication based on the generated hash
    df.dropDuplicates(["row_fingerprint"])
      .drop("row_fingerprint", "desc_fingerprint")
)
after = df_dedup.count()

print(f"Deduplicated: {before} -> {after} (removed {before - after})") #Deduplicated: 129971 -> 119986 (removed 9985)

3.9 Step 7 — Handling Missing and Abnormal Values

3.9.1 Purpose

To prepare the dataset for modeling, we need a clean and consistent numeric target (price) and reliable text categories.
This step focuses on: - fixing invalid numeric values, - imputing missing prices, - reducing extreme outliers, - and standardizing empty/invalid text fields.

These operations improve the stability of statistical summaries, ML models, and visualizations.

3.9.2 What We Did

3.9.2.1 1. Fix invalid price values

Prices ≤ 0 are not meaningful, so we convert them to NULL.

3.9.2.2 2. Clean text columns

After normalization, empty strings are set to NULL to avoid fake categories.

3.9.2.3 3. Median imputation of missing prices

For rows where price is missing, we fill it using the median price within
country_norm + variety_norm.
This preserves region-level pricing patterns and avoids bias from global averages.
(You can later switch to other grouping keys like province_norm + variety_norm.)

3.9.2.4 4. Winsorization to handle outliers

We clip extremely small or large prices using the 1% and 99% quantiles.
This keeps the data realistic while preventing a few extreme values from dominating models.

3.9.3 Result

All rows remain (119,986), but: - invalid prices are corrected, - missing prices are imputed consistently, - text fields are normalized, - and numeric outliers are controlled.

# Step 7 — Handling Missing and Abnormal Values

df_clean = df_dedup

# 1. Mark invalid prices as NULL
df_clean = df_clean.withColumn(
    "price",
    F.when(F.col("price").isNotNull() & (F.col("price") <= 0), None)
     .otherwise(F.col("price"))
)

# 2. Convert empty normalized text fields to NULL
for c in text_cols:
    norm = f"{c}_norm"
    if norm in df_clean.columns:
        df_clean = df_clean.withColumn(
            norm,
            F.when(F.trim(F.col(norm)) == "", None)
             .otherwise(F.col(norm))
        )

# 3. Median imputation for price
groupby_keys = [c for c in ["country_norm", "variety_norm"] if c in df_clean.columns]

if groupby_keys:
    med = (
        df_clean.groupBy(*groupby_keys)
        .agg(F.expr("percentile_approx(price, 0.5)").alias("med_price"))
    )

    df_clean = (
        df_clean.join(med, on=groupby_keys, how="left")
        .withColumn(
            "price_imputed",
            F.when(F.col("price").isNull(), F.col("med_price"))
             .otherwise(F.col("price"))
        )
        .drop("med_price")
    )
else:
    df_clean = df_clean.withColumn("price_imputed", F.col("price"))

# 4. Winsorization (1%–99%)
q = df_clean.approxQuantile("price_imputed", [0.01, 0.99], 0.01)
lower, upper = (q + [None, None])[:2]

if lower is not None and upper is not None:
    df_clean = df_clean.withColumn(
        "price_winsor",
        F.when(F.col("price_imputed") < lower, F.lit(lower))
         .when(F.col("price_imputed") > upper, F.lit(upper))
         .otherwise(F.col("price_imputed"))
    )
else:
    df_clean = df_clean.withColumn("price_winsor", F.col("price_imputed"))

print("Rows after cleaning:", df_clean.count())

3.10 Step 8 — Variety Normalization Mapping (Synonym Merging)

3.10.1 Purpose

Different wine regions often use different names for the same grape variety
(e.g., “pinot gris” vs. “pinot grigio,” “shiraz” vs. “syrah”).
If we do not unify these synonyms, analysis and modeling will treat them as separate categories.
This step ensures that varieties referring to the same grape are merged into a single canonical label.

3.10.2 What We Did

  1. Built a mapping table (VARIETY_MAP)
    • Each canonical grape variety lists its known aliases.
    • The mapping is extensible and can be expanded later.
  2. Created a reverse lookup
    • All aliases → canonical form
    • Broadcast to all Spark workers for efficient UDF lookup.
  3. Applied a UDF to normalize grape varieties
    • If a variety is an alias, convert it to the canonical name.
    • Mild rule: remove trailing “blend” where applicable.
    • Output stored in a new field: variety_canonical.

3.10.3 Result

The dataset now contains a standardized grape variety field, reducing category fragmentation and improving the reliability of later clustering, visualization, and ML tasks.

# reverse lookup: alias -> canonical
alias_to_canonical = {}
for canon, aliases in VARIETY_MAP.items():
    alias_to_canonical[canon] = canon
    for a in aliases:
        alias_to_canonical[a] = canon

broadcast_map = spark.sparkContext.broadcast(alias_to_canonical)

@F.udf(T.StringType()) # define UDF process:variety_norm → variety_canonical
def map_variety_norm(v):
    if v is None:
        return None
    v = v.strip().lower()
    if v in broadcast_map.value:
        return broadcast_map.value[v]
    if v.endswith(" blend"):
        return v.replace(" blend", "").strip()
    return v

# add canonical variety
if "variety_norm" in df_clean.columns:
    df_clean = df_clean.withColumn("variety_canonical", map_variety_norm(F.col("variety_norm")))
else:
    df_clean = df_clean.withColumn("variety_canonical", F.col("variety"))

3.11 Step 9 — Description Text Cleaning and TF-IDF Feature Extraction

3.11.1 Purpose

The wine description is the richest unstructured field in the dataset.
To use it for clustering, similarity search, or ML models, we need to convert the raw text into numerical features.
TF-IDF is a scalable and standard method in Spark to represent text meaning while down-weighting common words.

3.11.2 What We Did

  1. Clean the description text

    • Convert to lowercase
    • Remove non-English characters
      This creates a consistent text field for tokenization.

  2. Tokenize the text
    Using RegexTokenizer to split descriptions into word tokens.

  3. Remove stopwords
    Using StopWordsRemover to eliminate words that carry little semantic meaning.

  4. Convert tokens to term frequencies
    Using CountVectorizer to build a sparse TF matrix.
    minDF ensures we only keep meaningful terms across the corpus.

  5. Compute TF-IDF vectors
    Using IDF, producing the final numeric representation in column tfidf.

  6. Optional sampling
    To avoid memory pressure during debugging, the pipeline supports
    SAMPLE_FRACTION < 1.0 via environment variable.

3.11.3 Result

Each wine review now has a sparse TF-IDF vector capturing key descriptive terms.
These features are immediately usable for: - clustering wines by tasting profile,
- building recommendation systems,
- classifying wine varieties,
- or exploratory text analysis.

# Step 9 — Text Cleaning and TF-IDF

from pyspark.ml import Pipeline
from pyspark.ml.feature import RegexTokenizer, StopWordsRemover, CountVectorizer, IDF

# optional sampling (for debugging, 0.1 -> 1)
SAMPLE_FRACTION = float(os.environ.get("SAMPLE_FRACTION", "1.0"))
df_text = df_clean

if SAMPLE_FRACTION < 1.0:
    df_text = df_text.sample(False, SAMPLE_FRACTION, seed=42)

# clean description text
df_text = df_text.withColumn(
    "description_clean",
    F.lower(F.regexp_replace(F.col("description"), r"[^A-Za-z\s]+", " "))
)

tokenizer = RegexTokenizer(inputCol="description_clean", outputCol="tokens_raw", pattern="\W+") # "rich blackberry aroma" → ["rich", "blackberry", "aroma"]
remover = StopWordsRemover(inputCol="tokens_raw", outputCol="tokens") # rm something like "the" "and" "with" "this" words.
cv = CountVectorizer(inputCol="tokens", outputCol="tf", minDF=10) # Term Frequency
idf = IDF(inputCol="tf", outputCol="tfidf", minDocFreq=10) # Inverse Document Frequency

text_pipe = Pipeline(stages=[tokenizer, remover, cv, idf])
text_model = text_pipe.fit(df_text) 

df_text_feats = text_model.transform(df_text)

df_text_feats.select("description", "tokens").show(5, truncate=80)

3.12 Step 10 — Structured Feature Encoding (Indexing / One-Hot)

3.12.1 Purpose

After cleaning and text processing, we need all structured fields to be in a numerical format so they can be combined with TF-IDF features and used by ML models.
Spark models require vectors, not strings, so categorical columns must be transformed.

3.12.2 What We Did

  1. Index categorical variables
    We used StringIndexer to convert:

    • country_norm
    • variety_canonical
    • province_norm

    Each category is mapped to a numerical index.

  2. One-hot encode indexed fields
    Using OneHotEncoder to avoid imposing ordinal meaning on categorical variables.
    Each category becomes a sparse one-hot vector.

  3. Combine all features
    We then assembled:

    • numeric features (points, price_winsor)
    • one-hot encoded vectors
    • TF-IDF text features

    into a single feature vector using VectorAssembler.

  4. Output The final dataset df_ready contains a features column suitable for:

    • regression
    • classification
    • clustering
    • recommendation
    • or any ML algorithm in Spark MLlib. ```python from pyspark.ml.feature import StringIndexer, OneHotEncoder, VectorAssembler from pyspark.ml import Pipeline

numeric_cols = [c for c in ["points", "price_winsor"] if c in df_text_feats.columns]

# combine all features
assembler = VectorAssembler(
    inputCols=[*numeric_cols, *[f"{c}_oh" for c in categorical_cols], "tfidf"],
    outputCol="features"
)

struct_pipe = Pipeline(stages=[*indexers, *encoders, assembler])
struct_model = struct_pipe.fit(df_text_feats)
df_ready = struct_model.transform(df_text_feats)

3.15 Step 13 — Appendix: How to Reuse the Same Preprocessing Pipeline on New Data

3.15.1 Purpose

To ensure consistent predictions on future data, we do not refit any preprocessing.
Instead, we reuse the saved pipelines so that text cleaning, tokenization, TF-IDF, PCA, indexing, and one-hot encoding behave exactly the same as during training.

3.15.2 What We Did

  1. Clean the new dataset using the same steps as before
    (normalization, missing-value handling, etc.).

  2. Load the saved preprocessing models:

    • text_pipeline for description → tokens → TF-IDF → PCA
    • struct_pipeline for indexing, one-hot, and feature assembly

  3. Apply them in order: new_df_text = loaded_text.transform(new_df_clean) new_df_ready = loaded_struct.transform(new_df_text) The result includes the same tfidf_pca and features columns used for modeling.

3.15.3 Result

Any new wine review can be transformed into the same feature space as the training data, enabling consistent prediction, clustering, or similarity search.

3.17.1 1. Price Prediction (Regression)

Goal:

Reasons:

Model:

- Optional: Random Forest Regressor

Example question to explore:

3.17.2 2. Variety Classification (Multiclass)

Goal:
Predict the standardized grape variety (variety_canonical) based on description + country + province.

Reason
Variety is a strong label: tasting notes often directly imply varietal traits (“cherry + spice” → Pinot Noir).

Model:
- Logistic Regression (multiclass)
- Optional: Naive Bayes (works well with TF-IDF)

Example question to explore:
- Which words in tasting notes indicate a particular grape variety?
- Can a simple linear classifier distinguish red vs white varieties?

3.17.3 3. Country of Origin Prediction (Classification)

Goal:
Predict country_norm from a wine’s text description.

Reason:
Different regions use very distinct language (“minerality”, “oak”, “citrus”, etc.), so even simple models perform surprisingly well.

Model:
- Logistic Regression
- Optional: Random Forest

Example question to explore:
- Which countries are easiest or hardest to distinguish?
- What flavor words are most associated with France/US/Italy?
